# OwlDiffSearch

Gitの変更差分を、自然言語やキーワードから検索するVS Code拡張機能です。「タイムアウト時に再試行する変更」「認証トークンをログに出さない修正」のような目的から、関連する差分・コミット・ブランチを探し、VS Codeの差分エディタで確認できます。

**セットアップ、F5での起動、検索操作は [利用ガイド](docs/USAGE.md) を参照してください。**

## できること

- **変更内容から検索**：自然言語の意味検索と、コード中の識別子などを使ったキーワード検索に対応しています。
- **差分・コミット・ブランチを探す**：探したい対象に合わせて `Hunks`、`Commits`、`Branches` を選べます。
- **検索範囲を指定**：直近のコミット、From / Toで指定した履歴、作業ツリーの未コミット変更を検索できます。
- **履歴を見ながら比較**：コミットグラフから比較範囲を選び、検索結果からファイル単位またはコミット全体の差分を開けます。
- **ファイルを絞り込む**：パスやglobによるInclude / Excludeに対応しています。ドキュメントは既定で除外し、バイナリは検索対象外です。
- **埋め込みを再利用**：計算済みの差分はキャッシュし、変更された差分を中心に追加計算します。
- **Geminiで検索を補助**：任意で日本語の英訳、クエリ拡張、結果を確認しながら追加検索するAgentic検索を利用できます。

## 検索対象と方式

| 検索対象 | 内容 |
|---|---|
| `Hunks` | unified diffのハンク（変更箇所と前後の文脈）を検索します。 |
| `Commits` | コミット内の差分を検索し、コミット単位で結果を返します。 |
| `Branches` | 基準に選んだブランチには含まれていない変更を検索し、関連するブランチとコミットを表示します。 |

| 検索方式 | 内容 |
|---|---|
| `Semantic` | 検索文と差分の埋め込みのコサイン類似度で順位を付けます。 |
| `BM25` | 差分に含まれる語句を使って順位を付けます。 |
| `Hybrid` | Semanticと正規化したBM25スコアを組み合わせます。 |
| `Keyword` | スペースで区切ったすべての語句を含む差分を検索します。大文字・小文字は区別しません。 |

検索では変更内容を評価し、ブランチ名やコミットメッセージはスコアの計算に使いません。スコアは検索結果の関連度を表すもので、正解の確率ではありません。

## 実装の概要

VS Code拡張をTypeScriptで、ローカル検索サーバーをPythonで実装しています。

1. **拡張機能**が検索条件を受け取り、Git履歴の表示や差分エディタの操作を担当します。
2. **Pythonサーバー**がGitから指定範囲のパッチを取得し、指定されたファイルに絞り込み、ハンクやコミットごとにまとめます。
3. **検索処理**が意味の近さや語句の一致を評価し、結果を拡張機能に返します。

意味検索の既定モデルは `Shuu12121/NightOwl-CodeEmbedding` です。埋め込みをL2正規化し、FAISSの `IndexFlatIP` でコサイン類似度を計算します。Hybridは既定で `0.6 × Semantic + 0.4 × 正規化BM25` を使用します。

コミット検索のSemanticでは、変更されたファイルをそれぞれ評価し、最も高いスコアをそのコミットのスコアにします。BM25では、コミット内の差分をまとめて評価します。

ブランチ検索では、基準に選んだブランチに含まれていないコミットを検索します。それぞれのファイルの差分を評価し、最も高いスコアをそのブランチのスコアにします。基準のブランチは手動で指定するか、mainなどから自動で選びます。

埋め込みは差分テキストとモデル設定に基づいてキャッシュします。検索時にリポジトリのcheckoutやfetchは行わず、手元にある履歴と取得済みリモート追跡ブランチを使用します。

## ローカル処理と外部API

通常の差分取得・埋め込み生成・検索はローカルで実行します。初回セットアップとモデル取得にはインターネット接続が必要です。

Gemini連携は任意で、APIキーを設定して有効にした場合に使用します。翻訳・クエリ拡張では検索文を送信し、Agentic検索では検索目的に加えて候補のタイトル・パス・コミットID・差分の一部などを送信します。Agentic検索はローカルの検索ツールを呼び出し、結果を確認してクエリや検索方式を調整します。
